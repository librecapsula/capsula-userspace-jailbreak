# capsula-jb — root на колонках VK Capsula через перезапись userspace

Джейлбрейк VK Capsula методом перезаписи userspace:
раздел **userdata не подписан** и свободно перезаписывается
пользователем — кладём в него оверлей с фабричным `adbd`, и после
перезагрузки колонка видна как ADB-устройство (`2207:0006`):
`adb shell` даёт **root без авторизации**. Остальные разделы не
изменяются, стоковая прошивка продолжает работать как есть.

Поддерживаемые платы:

- **Capsule-14, Capsule-15** и **Capsula Мини на Rockchip RK3308B**
  (ранняя ревизия `CapsulaDot_Main_V1.0`) — полный сценарий джейлбрейка.
  Лоадер для всех один — подписанный usbplug из OTA Capsule-14 (во всех
  актуальных прошивках rk3308 это одна и та же сборка), он скачивается
  и кешируется автоматически.
- **Capsula Мини на Amlogic A113X** (поздняя ревизия `MRC02B_Main`,
  `1b8e:c003`) — распознавание платы, bring-up в download-режим u-boot и
  passthrough команд u-boot (`capsula-jb aml`); сценарий прошивки для
  этой платы в разработке. Стоковый u-boot поднимает фабричное
  download-окно при каждом включении (~0.5 с) и не запаролен —
  инструмент ловит его сам, разбирать колонку не нужно.

`capsula-jb` — самодостаточный кроссплатформенный инструмент (Linux,
Windows, macOS): Rockchip USB-протоколы, протокол Amlogic update,
форматы OTA и ext2/3/4 реализованы нативно на Rust — без libusb,
rkdeveloptool, e2fsprogs и без root (с udev-правилами на Linux).

## Установка

Готовые сборки — в [Releases](../../releases): архивы под Windows
(x64), Linux (x64/arm64) и macOS (x64/arm64). В каждом архиве —
бинарник, README, QUICKSTART.txt и AGENTS.md; в Windows-архив
дополнительно вложены Zadig и официальный установщик USB-драйверов
Rockchip.

- **Windows**: распакуйте архив и запускайте `capsula-jb.exe` — Windows
  запросит права администратора (UAC) один раз, в самом начале: весь
  инструмент работает повышенным (манифест requireAdministrator), так
  как управляет драйверами. USB-драйверы ставятся автоматически:
  инструмент сам устанавливает WinUSB-пакеты (сгенерированные
  Zadig/libwdi, зашиты в бинарник) с их сертификатами в машинные
  хранилища, сам перевязывает плату на каждом смене её USB-личины
  (лоадер 330d, MaskROM/usbplug 330e) и сам побеждает вендорский
  драйвер Rockusb, если тот установлен. Из обычного терминала
  повышенный процесс получит собственное окно консоли (с паузой в
  конце, чтобы вывод не пропал); из уже повышенного — работает в том
  же окне. Ручной режим (Zadig из архива) и переключение обратно на
  вендорский драйвер для RKDevTool — в `DRIVER-SETUP.txt`.
  Для Amlogic мини (`1B8E:C003`) WinUSB пока настраивается вручную —
  см. `DRIVER-SETUP.txt`. Автоматическая установка относится к Rockchip.
- **macOS**: если бинарник заблокирован Gatekeeper после скачивания
  браузером — `xattr -d com.apple.quarantine capsula-jb`.
- **Linux**: для работы без root установите udev-правила (см. Полезное).

Сборка из исходников: `cargo build --release` (нужен Rust и
C-компилятор — lwext4 собирается через `cc`).

## Быстрый старт

```sh
capsula-jb               # полный сценарий (см. ниже)
adb shell                # root по USB, без авторизации
```

ADB доступен **и по USB, и по Wi-Fi** — одновременно (подробнее в
разделе «Подключение»).

Только дампы (без записи на плату):

```sh
capsula-jb backup
```

## Сценарий (команда по умолчанию)

0. **Ожидание платы**: инструмент предлагает подключить колонку кабелем
   и подать питание и следит за шиной — что подключится (Rockchip в
   download-режиме или Amlogic мини), такой путь и выбирается. Для
   Rockchip-плат: войдите в режим rockchip loader (подсказка печатается
   во время ожидания, инструмент подхватывает плату сам). Для Amlogic
   мини: просто включите колонку при подключённом кабеле — u-boot сам
   поднимает download-окно.
1. **Лоадер** (Rockchip): скачивается OTA Capsule-14, из неё извлекается
   подписанный лоадер; кеш — `ota/loader.bin` (при наличии кеша ничего
   не качается). Лоадер один на все поддерживаемые платы.
2. **Плата**: ждём появления устройства в режиме rockchip loader
   (`2207:330d`/`330e`). Загружаем наш usbplug в RAM (флеш не трогается),
   сверяем сигнатуры в DRAM.
3. **Дамп**: RAM-патчем поднимаем предел чтения usbplug (обход маски
   0xCC — без патча всё выше 32 МиБ читается как 0xCC) и снимаем
   полный дамп всех GPT-разделов в `backup/` с SHA256-суммами.
4. **Оверлей**: на основе сдампленного userdata собираем образ с
   нашими файлами в `/overlay/upper` — верхнем слое overlayfs.
   Файловая система (ext2) правится библиотекой
   [ext4-lwext4](https://crates.io/crates/ext4-lwext4), остальное
   содержимое дампа сохраняется.
5. **Запись**: собираем userdata обратно в раздел (единственная запись
   во флеш за весь сценарий).
6. **Перезагрузка**: плата уходит в нормальную загрузку, инструмент
   ждёт устойчивого появления adb-гаджета `2207:0006` (сток без adbd
   мигает гаджетом меньше секунды — мигание не считается успехом).

`capsula-jb backup` выполняет шаги 1–3 и останавливается.

## Как это работает (проверено по rootfs из OTA 44.90)

Стоковая прошивка сама предоставляет механизм — overlay поверх
read-only rootfs:

- `S02mount-data.sh`: e2fsck -yf, при невозможности починить — mke2fs;
  монтирует userdata как **ext2** в `/data`;
- `S23overlayfs.sh`: `overlay lowerdir=/ upperdir=/data/overlay/upper
  workdir=/data/overlay/work` + pivot_root — файлы из
  `userdata:/overlay/upper` оказываются в корне системы;
- `S50usbdevice`: поднимает USB-гаджет ffs.adb и стартует `adbd &`
  безусловно. В стоке 44.90 бинарника adbd в rootfs нет — гаджет
  мигает на секунду и умирает.

Мы кладём в `userdata:/overlay/upper` три файла, и после загрузки они
появляются в корне: `/usr/bin/adbd`, `/etc/init.d/.usb_config` (флаг
adb для прошивок, где он разбирается) и маркер `/etc/jailbreak`.
Подписанные разделы не трогаются, dm-verity и голосовой стек работают
как в стоке.

`adbd` — собственная сборка (исходники android-tools 4.2.2 + патч
«listen on TCP alongside USB»), слинкован под сток: glibc ≤ 2.33,
libcrypto.so.1.1. Он слушает **одновременно USB и TCP:5555** — после
подключения колонки к Wi-Fi доступен и `adb connect <ip>:5555`
(порт меняется переменной окружения `ADBD_TCP_PORT` при старте adbd).
Сборка воспроизводится герметично: `docker/adbd` (Debian bullseye,
кросс-тулчейн и libcrypto через multiarch) — `docker build -t capsula-adbd
docker/adbd && docker run --rm -v docker/adbd:/work capsula-adbd
/work/build.sh`.

Сброс к заводским настройкам вычищает `/data` (включая
`/data/overlay`) — джейлбрейк откатывается, колонка возвращается к
стоку.

## Как войти в режим rockchip loader

**Большие Капсулы (Capsule-14/15):** выключить питание, снять нижнюю
накладку, подключить micro-USB (OTG) к компьютеру. Иголкой зажать
кнопку Recovery (нижнее из двух отверстий над micro-USB, дальше от
разъёма питания) и, удерживая, подать питание; отпустить через
несколько секунд. Плата появляется как `2207:330d`.

**Capsula Мини на Rockchip:** кнопки Recovery нет. Зажать сенсорную
кнопку при подаче питания, либо Ctrl+D в UART-консоли с подключённым
OTG (rockusb, `2207:330d`), либо Ctrl+B (MaskROM, `2207:330e`).

**Capsula Мини на Amlogic:** ничего нажимать не нужно — стоковый u-boot
при каждом включении поднимает фабричный download-режим (`1b8e:c003`)
примерно на полсекунды; запущенный `capsula-jb` ловит это окно сам. Окно
пропущено — выключите и снова включите питание при подключённом кабеле.

## Amlogic мини (`capsula-jb aml`)

Поздние ревизии Capsula Мини (плата MRC02B, SoC Amlogic A113X) видны
на шине как `1b8e:c003` в двух стадиях: BootROM и u-boot burning gadget
(фабричный download-режим u-boot, который и появляется при каждом
старте). Протокол реализован нативно (vendor-запросы EP0 + bulk,
wire-формат сверен с device-стороной u-boot v2_burning и pyamlboot):

```sh
capsula-jb aml                              # identify платы (стадия, версия)
capsula-jb aml "printenv bootdelay"         # выполнить команду u-boot
capsula-jb monitor                          # события шины обоих вендоров
```

`capsula-jb backup` для A113X сохраняет новый каталог `backup/amlogic-*/`:
экспорт окружения (`env-export.bin`, `env.txt`), восемь разделов,
пять служебных областей (`reserved-*.bin`) и `nand-full.raw.bin` —
полный NAND 256 MiB вместе с OOB (264 MiB, страницы 2048+64 байта).
Каждый образ читается с колонки одним проходом, без повторного чтения
NAND или RAM для сравнения. SHA256 проверяет сохранённые файлы;
он не подтверждает повторяемость чтения флеш-памяти.

Перед чтением каждого раздела `store size` сообщает доступную логическую
ёмкость без плохих erase-блоков. В manifest для разделов `physical_size` —
физический размер из карты, `expected` — логический размер от загрузчика,
`actual` — сохранённые байты. Например, при одном плохом блоке 256 КиБ
в `data` физические 78 MiB дают логические 77,75 MiB. Образ не дополняется
нулями; физический NAND вместе с плохими блоками остаётся в raw-снимке.

`manifest.json` содержит размеры, SHA256 и статус: `complete` — все файлы
полного ожидаемого размера (для разделов — логического); `warnings` — один или несколько разделов короче ожидаемого;
`failed`/`running` — бекап не завершён. Короткие и прерванные файлы остаются
с суффиксом `.partial`. Дополнительно сохраняется `SHA256SUMS.txt`.
Повторный запуск создаёт отдельный каталог. При обрыве USB автоматического
переподключения и продолжения нет. Этот формат предназначен для сохранения
данных; команды восстановления из него пока нет. Обычный запуск без
`backup` для Amlogic по-прежнему только определяет плату.

Команды идут через AM_REQ_BULKCMD в диспетчер burning-команд u-boot
(`md`/`download`/`upload`/`verify`/`save_setting`/...; неизвестные
диспетчеру строки уходят в `run_command` — их вывод виден только на
UART). Несколько команд за раз выполняются внутри одного пойманного
окна; `upload mem <addr> normal <size>` тул распознаёт и печатает
hexdump данных. Проверено на живой плате: открытие +9 мс, identify
+10 мс, `md` +10 мс, `upload mem` +30 мс — по этому пути читается,
например, живой DTB из DRAM на 0x01000000.

Ограничения окна: download-режим живёт ~1 с после включения и
**закрывается независимо от identify** — перед каждым запуском `aml`
передёргивайте питание. Успевают только лёгкие команды: тяжёлые
выводом в UART (`printenv` без аргументов) не укладываются в окно —
устройство уходит с шины посреди команды. Сценария прошивки для
Amlogic-плат пока нет: разделы мини на UBI с вендорской ECC, и
безопасная запись потребует отдельной работы.

## Подключение: USB и Wi-Fi

Наш adbd слушает USB-гаджет и TCP **одновременно** — колонка доступна
обоими способами, переключаться не нужно.

**USB**: после джейлбрейка колонка постоянно видна как ADB-устройство
(`2207:0006`):

```sh
adb devices && adb shell      # root, без авторизации
```

**Wi-Fi**: работает, как только колонка подключена к сети (настраивается
в приложении как обычно). Узнайте IP колонки и подключитесь:

```sh
adb shell ifconfig wlan0           # inet addr:192.168.1.42 (или из роутера)
adb connect 192.168.1.42:5555
adb shell
```

Порт по умолчанию **5555**; меняется переменной окружения
`ADBD_TCP_PORT` при старте adbd (0 — отключить TCP). Wi-Fi-доступ
живёт, пока жив джейлбрейк: сброс к заводским настройкам вычищает
`/data` вместе с оверлеем.

## Каталоги данных

- `ota/` — OTA-пакеты и извлечённый `loader.bin` (кеш);
- `backup/` — дампы разделов платы (`NN_имя.img`, `partition_table.tsv`,
  `SHA256SUMS.txt`); дамп не модифицируется, оверлей собирается в копии;
- `work/` — промежуточные образы (`userdata.img` с оверлеем).

## Полезное

- `--wait SEC` — таймаут ожидания платы (0 = бесконечно, по умолчанию);
- `--yes` — не спрашивать подтверждение перед записью userdata
  (скрипты и автоматизация). Без флага перед записью печатается
  `proceed? [y/N]` и ждётся ответ; в неинтерактивном окружении (CI,
  LLM-агенты, перенаправленный stdin) инструмент завершится ошибкой,
  ничего не записав, с подсказкой перезапустить с `--yes`. Агентам:
  получив такую ошибку, согласуйте запись с пользователем и повторите
  с `--yes` — сами не подтверждайте перепрошивку автоматически;
- `--format-userdata` — не патчить дамп, а отформатировать userdata как
  чистый ext2 и положить только оверлей (существующее содержимое
  userdata теряется; выручает, если раздел на плате не отформатирован
  или его ФС не читается);
- `capsula-jb monitor` — живой лог событий download-режимов на шине
  (`2207:*` Rockchip и `1b8e:c003` Amlogic);
- `capsula-jb aml "<u-boot команда>"` — passthrough команд u-boot на
  Amlogic мини (см. раздел выше);
- ADB по Wi-Fi: см. раздел «Подключение: USB и Wi-Fi»;
- Linux без root: `sudo cp resources/udev/99-capsula-jailbreak.rules
  /etc/udev/rules.d/ && sudo udevadm control --reload`.
- Инструкция для LLM-агентов по прошивке — правила подтверждения
  записи (`--yes`), тумблер USB-драйверов WinUSB ↔ Rockusb с проверкой
  привязки из командной строки: `AGENTS.md` в релизном архиве
  (`resources/packaging/AGENTS.md` в репозитории). Корневой
  `AGENTS.md` — инструкция по разработке.

```
crates/
  usbcore/    Общий USB-слой: транспорт nusb (WinUSB на Windows) —
              vendor control/bulk, мок для тестов. Переиспользуется
              всеми вендорскими стеками.
  rockusb/    Rockchip USB-стек: MaskROM DownloadBoot (0x471/0x472),
              rockusb CBW/CSW (чтение/запись LBA и RAM), режимы и
              монитор шины 2207:*. Нативный порт xrock.
  amlogic/    Amlogic update-протокол (1b8e:c003): identify/стадии,
              память (простая/крупная), run, bulkcmd/tplcmd, media
              download/upload с add_sum; порт wire-формата update-тула
              (device-сторона: u-boot v2_burning, host: pyamlboot).
  jb-core/    Домен: конфигурация, GPT, дамп (RAM-патч 0xCC),
              OTA/RKFW, оверлей userdata (ext4-lwext4), запись раздела;
              unified wait/dispatch по вендорам (target.rs).
  win-drv/    Windows: автоматическая установка/перевязка WinUSB
              для Rockchip (Zadig-пакеты в бинарнике, UAC).
  jb-cli/     capsula-jb — CLI.
resources/
  config.toml Общая конфигурация: код OTA, константы RAM-патча usbplug,
              подсказки по входу в download-режимы (оба вендора).
  drivers/    WinUSB-пакеты (INF+CAT+CER, сгенерированы Zadig/libwdi)
              для 330D и 330E — вшиваются в бинарник крейтом win-drv.
  overlay/    adbd + флаг USB-гаджета (вшиваются в userdata).
```

Бинарные образцы прошивок в репозитории не хранятся и не
распространяются: тесты работают на синтетических образах и моках;
единственный тест с реальными данными сам скачивает OTA с VK CDN в
момент запуска (выключен по умолчанию, см. tests/README.md).

Зависимость `ext4-lwext4` компилирует C-библиотеку lwext4 через `cc`
(нужен C-компилятор при сборке), рантайм-зависимостей нет. Лицензия
обвязки — MIT/Apache-2.0; флаги `gpl*` самой библиотеки не
используются. WinUSB-пакеты в `resources/drivers/` сгенерированы
Zadig/libwdi (LGPL, Pete Batard) — условия те же, что и для вложенного
в архивы `zadig-2.9.exe`; см. `resources/drivers/winusb/README.md`.

## Разработка

Amlogic: `AmlogicSession::upload_store_to` читает раздел в произвольный
`std::io::Write` с буфером до 64 КиБ. Полученные байты сразу передаются
писателю; при обрыве USB ранее записанный префикс остаётся у вызывающего.
Ошибки писателя и USB различаются. Нулевой upload head означает короткий
stream, но не доказывает bad block; для RAM требуется точный размер.
Статусы `Continue:` ограничены общим дедлайном 30 с (уже начатая передача
завершается по таймауту транспорта). Открытие Amlogic требует единственной
платы на шине; BootROM определяется без burning-prime, а команды storage
в CLI доступны только для TPL. Команда `backup` использует этот потоковый API для Amlogic-разделов.

```sh
cargo test --workspace
```

Тесты userdata гоняют настоящий lwext4 на синтетических образах;
протокольные тесты — на MockTransport (без железа). Тесты userdata
сериализованы общим мьютексом: у lwext4 глобальное состояние.
