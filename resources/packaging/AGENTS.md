# AGENTS.md — инструкция для LLM-агентов: прошивка колонки

Правила помощи пользователю в джейлбрейке VK Capsula этим
инструментом. Суть: capsula-jb переписывает единственный раздел флеша
(userdata) — только с явного согласия пользователя; установку
USB-драйверов на Windows инструмент делает сам, и UAC-запрос является
согласием пользователя на неё.

## Подтверждение записи на устройство

Перед записью userdata инструмент печатает `proceed? [y/N]`. При
неинтерактивном stdin (CI, агент) он завершается ошибкой, ничего не
записав. Получив такую ошибку, согласуйте запись с пользователем и
перезапустите с `--yes`. **Никогда не добавляйте `--yes` по своей
инициативе.** `capsula-jb backup` ничего не пишет и подтверждений не
спрашивает.

## USB-драйвер на Windows

capsula-jb управляет драйверами сам: весь инструмент работает
повышенным (манифест requireAdministrator — Windows показывает ОДИН
UAC-запрос в самом начале, до любой работы), ставит WinUSB-пакеты
(зашиты в бинарник, сгенерированы Zadig/libwdi) с их сертификатами в
машинные хранилища и на протяжении всей сессии перевязывает плату на
каждой смене её USB-личины, переживая даже установленную вендорскую
Rockusb (RKDevTool). **Агенту ничего вручную делать не нужно и не
нужно просить пользователя запускать Zadig**; для автоматизации
запускайте exe из уже повышенного контекста (тогда UAC-окно не
появляется, а вывод остаётся в вашем перенаправлении; из обычного
терминала вывод уходит в собственное окно повышенного процесса).
От пользователя требуется одно: нажать «Да» в UAC.

Официальные утилиты (RKDevTool, upgrade_tool, FactoryTool) работают
через вендорский **Rockusb**, который ставит DriverAssistant из
`RockchipUSBDriver.zip`. Windows разрешает устройству один драйвер —
это тумблер; инструкции по переключению туда-обратно — в
`DRIVER-SETUP.txt` (закройте capsula-jb перед возвратом на Rockusb —
иначе его сессия тут же перевяжет плату обратно на WinUSB).

**Диагностика** (если что-то пошло не так). `capsula-jb monitor` лишь
перечисляет шину и видит плату при любом драйвере — это НЕ способ
проверить драйвер. Привязка:

```powershell
Get-PnpDevice | Where-Object { $_.InstanceId -match 'VID_2207&PID_330D' } |
  Get-PnpDeviceProperty -KeyName DEVPKEY_Device_Service | Format-List KeyName,Data
```

`Data: WinUSB` — готово к capsula-jb. Лог драйверной сессии:
`%TEMP%\capsula-jb-winusb-<pid>\session.log`. Ручной запасной путь
(Zadig из архива) описан в `DRIVER-SETUP.txt`. После джейлбрейка adb по
USB (гаджет `2207:0006`) потребует WinUSB-классного драйвера и для
самого adb (подойдёт любой Google/Android SDK-драйвер); adb по Wi-Fi
(`adb connect <ip>:5555`) не требует ничего.

## Linux: доступ без root

Установите udev-правило из архива и перечитайте правила:

```sh
sudo cp 99-capsula-jailbreak.rules /etc/udev/rules.d/ && sudo udevadm control --reload
```

После этого capsula-jb работает от обычного пользователя.
