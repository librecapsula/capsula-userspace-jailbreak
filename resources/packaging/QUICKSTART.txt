capsula-jb — быстрый старт
==========================

1. Запустите capsula-jb.
   Windows спросит права администратора — это нормально, так и надо.
   macOS: если бинарник заблокирован —
     xattr -d com.apple.quarantine capsula-jb
   Linux: для работы без root поставьте udev-правило из архива (см. README).

2. Введите колонку в режим лоадера: выключите питание, снимите нижнюю
   накладку, подключите micro-USB (OTG) к компьютеру. Иголкой зажмите
   Recovery — нижнее из двух отверстий над micro-USB — и, удерживая,
   подайте питание. Отпустите через пару секунд.
   (Мини: кнопки Recovery нет — держите сенсорную кнопку при включении.)

3. capsula-jb сделает всё сам (лоадер уже вшит в бинарник, интернет
   не нужен): снимет полный бэкап в backup/<серийник>/, положит в
   userdata оверлей с adbd и перезагрузит колонку. Перед записью
   спросит «продолжить? [y/N]».
   Если для этого серийника уже есть валидный бэкап — дамп пропускается.

   Крайний случай — capsula-jb --no-backup: не проверять и не снимать
   бэкап вовсе, userdata собирается с нуля (текущее содержимое теряется;
   пригодится, например, при битом каталоге бэкапа).

   Другие команды:
     capsula-jb backup     только дамп, на колонку не пишется
     capsula-jb --help     все опции

   Колонки первого поколения («подарочные») распознаются сами: бэкапа
   на них нет, инструмент предложит прошить userdata с нуля — его
   текущее содержимое при этом теряется.

4. Когда инструмент напишет «ADB поднят»:
     adb devices && adb shell     # root, без авторизации
   По Wi-Fi: adb connect <ip-колонки>:5555

Для скриптов и агентов: с неинтерактивным stdin подтверждение записи
завершается ошибкой, ничего не записав — перезапустите с --yes, когда
запись согласована. Правила для агентов — AGENTS.md. Подробности и
решение проблем — README.md.
