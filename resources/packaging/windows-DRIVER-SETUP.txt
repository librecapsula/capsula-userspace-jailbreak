USB drivers on Windows
======================

For Rockchip, capsula-jb manages the drivers itself. This file
explains what it does and covers the manual fallback and the toggle
back to the vendor driver.

How the automatic mode works
----------------------------
capsula-jb talks to the board (2207:330d/330e) through WinUSB, but a
board hops between USB identities while it is being worked on (loader
330d, MaskROM and usbplug 330e), and Windows picks a driver for every
newly created device node — a vendor "Rockusb" package, when installed,
outranks WinUSB INFs there.

capsula-jb therefore:

- requires administrator rights for the whole process (a
  requireAdministrator UAC manifest embedded in the exe): one prompt
  at the very start, before any work begins, so nothing ever runs
  twice or races an elevation;
- carries the WinUSB driver packages (generated by Zadig/libwdi; see
  resources/drivers/winusb in the source tree) inside the binary;
- installs their certificates into the machine Root/TrustedPublisher
  stores and the packages through the same Windows API
  (UpdateDriverForPlugAndPlayDevices) Zadig uses;
- keeps watching the USB bus for the whole session and re-binds any
  Rockchip device node a vendor driver has grabbed, retrying the
  affected step automatically.

Started from a normal (non-admin) console or by a double-click, the
elevated tool runs in its own console window and waits for Enter at
the end so the output stays readable; from an already elevated console
it runs in place. The driver session log is in
%TEMP%\capsula-jb-winusb-<pid>\session.log.

Two families of tools, one device
---------------------------------
- capsula-jb opens the board through WinUSB;
- official Rockchip tools (RKDevTool, upgrade_tool, FactoryTool) use
  the vendor "Rockusb" driver installed by DriverAssistant
  (RockchipUSBDriver.zip in this archive).

The binding is per board serial and can be switched back and forth.

Manual WinUSB binding (fallback)
--------------------------------
Only if the automatic mode could not start (e.g. UAC was declined and
the run failed with a driver error):

1. Put the speaker into rockchip loader mode (see QUICKSTART.txt).
2. Run zadig-2.9.exe from this folder.
3. Options -> enable "List All Devices".
4. Select the device with USB ID 2207:330D. Zadig lists devices by
   their USB product string — in loader mode it is typically "USB
   download gadget" (Device Manager, in contrast, shows the
   driver-provided name "Rockusb Device"); go by the USB ID, not by
   the display name. Pick WinUSB with the arrows, click "Replace
   Driver". Repeat for 2207:330E if you plan to use MaskROM-entry
   boards (the tool re-binds 330E automatically whenever it can).
5. Verify the binding:

   powershell -NoProfile -Command "Get-PnpDevice | Where-Object { $_.InstanceId -match 'VID_2207&PID_330D' } | Get-PnpDeviceProperty -KeyName DEVPKEY_Device_Service | Format-List KeyName,Data"

   Data: WinUSB — done. (capsula-jb monitor shows the board under any
   driver; it lists the bus and is NOT a driver check.)

Switch back to the vendor driver (to run RKDevTool & friends)
-------------------------------------------------------------
Zadig/capsula-jb bindings outrank the vendor's generic INF —
re-running DriverAssistant alone will NOT take the board back. Instead:

1. Device Manager -> find the board -> Uninstall device, check
   "Attempt to remove the driver for this device" (removes the
   WinUSB INF bound to it).
2. Make sure the vendor package is installed (unpack
   RockchipUSBDriver.zip once, run DriverInstall.exe from the
   unpacked DriverAssitant_v5.14 folder, wait for "Install OK"),
   then Scan for hardware changes (or replug the board).
3. Verify with the same PowerShell check: Data: Rockusb.

Note: while capsula-jb is running, its session keeps re-binding the
board to WinUSB — close capsula-jb before switching to RKDevTool.

Notes
-----
- DriverAssistant only installs USB drivers; it does not touch disks,
  firmware or anything else.
- After the jailbreak, USB adb (the 2207:0006 gadget) needs a
  WinUSB-class driver for your adb as well; any installed
  Google/Android SDK driver works, and adb over Wi-Fi
  (adb connect <speaker-ip>:5555) needs no driver at all.

Amlogic minis (manual setup)
---------------------------
Late minis enumerate as 1B8E:C003. The automatic driver installation
above covers Rockchip 2207:330d/330e only. For Amlogic, use Zadig from
the archive: Options -> List All Devices -> select the 1B8E:C003
download device -> target driver WinUSB -> Install. The device is
available only during its download window; power-cycle the speaker
again after installing the driver.
