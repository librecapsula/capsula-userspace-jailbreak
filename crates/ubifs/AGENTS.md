# AGENTS.md — the ubifs crate

A standalone, publishable pure-Rust UBIFS/UBI library (its own cargo
workspace, not a member of the repo-root workspace). Documentation and
comments are English-only; nothing in `src/` may assume the Capsula
Mini or reference the host project.

## Layout

- `src/media.rs` — on-flash nodes and constants (a port of
  `fs/ubifs/ubifs-media.h`); `key.rs`, `crc.rs`, `geometry.rs`,
  `lpt.rs`, `tnc.rs` — format mechanics (ports of key.h/lpt.c etc.);
- `src/mkfs.rs` + `tree.rs` + `walk.rs` + `devtable.rs` — the
  mkfs.ubifs port (builder, tree model, directory walker, `-D` table);
- `src/compress.rs` — decompression and mkfs-compatible compression;
- `src/reader.rs` — the volume reader (post-replay view);
  `src/journal.rs` — log/bud/orphan parsing and replay inputs;
- `src/ubi.rs` — EC/VID headers, volume table, dump parsing;
  `src/ubinize.rs` — the ubinize port (ini configs, image building);
- `src/check.rs` — the fsck.ubifs-style checker (detection only).

## Commands (run from `crates/ubifs`)

```sh
cargo test                     # everything offline, all suites
bash tests/mkfs-parity.sh      # byte parity vs real mkfs.ubifs (docker)
bash tests/ubinize-parity.sh   # byte parity vs real ubinize (docker)
bash tests/data/gen.sh         # regenerate the committed corpus (docker)
UBIFS_STOCK_DUMP=<file> cargo test   # plug a real dump into stock_dump.rs
```

## Rules

- Byte parity of the builders (`-x none`, ubinize) must never break:
  the offline corpus tests (`tests/official_images.rs`) and the docker
  harnesses are the gates. The format subtleties that are easy to
  break are listed in README.md ("Format notes that are easy to
  break").
- Compressed write payloads are deliberately NOT byte-identical to
  mkfs.ubifs (its lzo1x_999 is GPL; zlib params are the kernel's) —
  valid, kernel-readable streams only. Do not chase byte parity there.
- `tests/data/` is a committed corpus generated by the real tools; if
  the generator changes, regenerate and commit, do not hand-edit.
- The kernel and mtd-utils sources in `work/reference/` (repo root,
  git-ignored) are the format specification — reading them is fine,
  copying code is not (GPL).
